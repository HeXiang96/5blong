## 9. 已知的坑（黑名单，别再踩）

### 9.1 防火墙有两道门
阿里云**安全组**和服务器里的 **ufw** 是两道独立关卡。中继端口当时两边都开了才通。
`deploy/setup-turn.sh` 已把 ufw 规则固化（只 allow，绝不删规则，尤其不能碰 SSH）。

### 9.2 阿里云是 1:1 NAT
网卡上只有私网地址（`172.22.x`）。coturn **必须**写
`external-ip=<公网IP>/<私网IP>`——仓库里的 `deploy/turnserver.conf` 用的是
`__PUBLIC_IP__/__PRIVATE_IP__` 占位符，由 `deploy/setup-turn.sh` 安装时注入
（`sudo bash setup-turn.sh <公网IP> <私网IP>`）。不写就会把私网地址当候选发出去，谁都连不上。

### 9.3 nginx 的匹配优先级
`/peerjs/inbox` 用的是**精确匹配** `location = /peerjs/inbox`，必须能压过前缀 `location /peerjs`。
漏了这条的表现：收件箱连到信令进程被拒，客户端**安静地退化成轮询**，看不出错。
后台路径同理（`/admin` 等漏了会落到 SPA 兜底返回首页）。

### 9.4 全局 CORS 中间件别设 Content-Type
一旦给所有响应设 `application/json`，后台 HTML 会以 JSON 类型返回，**浏览器把源码显示成纯文本**，
状态码却一直是 200 —— 只有截图才看得出来。

### 9.5 客户端契约（动了会坏）
- 密码哈希 `pbkdf2$<rounds>$<hex>`，rounds 固定 100000（Workers 的硬上限，别再升）。
- 会话 cookie 名 `5blong_sess`，`SameSite=Lax` → **前端与接口必须同域**。
  这就是静态站和接口放在同一台机器的原因。
- `/ice` 状态码契约：200 = `{iceServers:[...]}`；501 = 没配（客户端静默退回纯 STUN）。别改语义。
- 收件箱推送**只带类型不带内容**（`INVITE`/`FRIEND`），界面数据永远来自快照接口 —— 防伪造。
- 房码正则只准用 `protocol.ts` 的 `isRoomCode/normalizeCode/ROOM_CODE_LEN`（历史上复制两份出过事故）。
- `member-menu.html` 夹具的 `?n=8`：第 1 位成员固定 `id="guest"`，动它会弄哑老用例。

### 9.6 SSH 曾经整段失联
2026-11-03 10:28 左右，`5blong.site:22` TCP 可连但 sshd 不发 banner，网站（HTTP）完全正常。
一小时里开了几十次 SSH 连接，怀疑是 sshd 连接堆积或瞬时资源压力。网站不受影响。
恢复手段（未验证）：阿里云控制台 → Workbench 远程连接 → `systemctl restart sshd`。
**教训**：批量操作尽量合并成少数几次 SSH 会话，不要每条命令开一个。

### 9.7 环境里写文件会变字符
这个工作环境曾把 heredoc 里的日期/密码字面量改写成别的（如 `2026-11-02` → `2026-74-56`）。
**写完必须回读核对**；改已有文件用 `read_bytes/write_bytes`（仓库里 tsx 是 CRLF/LF 混合的）。

### 9.8 无头浏览器截图会骗人
Windows 上 headless 最小窗口宽约 500px：请求 390 会按 500 布局再裁切，看起来像"溢出"。
要真实移动端视图，用定宽 iframe（`tests/fixtures/overflow-probe.html`）。

### 9.9 只测 STUN 不等于中继通
STUN 不需要认证，凭据错了它照样回。要验证中继必须做完整 Allocate（`turn-check.mjs`），
它能一次证明：UDP 可达 / HMAC 凭据 / external-ip / 端口段四件事。

- 房主关房没有显式通知（HTTP 无连接可监听），靠 90 秒空闲清扫收尾。

## 12. 设计决策的"为什么"（避免重新讨论）

| 决定 | 理由 |
|---|---|
| 用 `node:sqlite` 不用 better-sqlite3 | 后者在 Windows 要 VS 编译、服务器要 gcc；内置模块零依赖，部署只剩装 Node |
| `db.mjs` 仿造 D1 API | worker 的 1400 行 SQL 原样搬，不重写不出新 bug |
| 静态站和接口放同一台机器 | 分开就是跨站，`SameSite=Lax` 的 cookie 不带 → 全员掉登录 |
| 8788/9000 只绑 127.0.0.1 | 对外一律走 nginx（TLS），不给明文 ws 留口子 |
| 收件箱放接口进程不放信令进程 | 推送触发点就在邀请/好友写入路径上，同进程一次函数调用 |
| 遥测走 HTTP 不走信令 WS | 不动信令（改错是整房连不上）；HTTP 可重试、无长连接负担 |
| TURN 自建而不用 CF | 中继路径 200ms → 37ms；凭据本地签发，消灭"2.5 秒超时"这类故障 |
| TURN 端口限 1000 个 | 每会话 2 端口，够 ~500 路并发；安全组一条规则搞定 |
| 小房间保留 P2P | 直连音质与延迟更好，SFU 只为解决"人多" |
| 不做"带宽不足降分辨率" | 历史上做过两次都翻车（见 README 共享屏幕章节）；分辨率交给 CPU 受限触发 |
| v2.0 = 语音换混合转发 | 13 人 = 78 条媒体连接、每人编 12 路；带宽不是瓶颈，编码才是（见 docs/V2-PLAN.md） |
