## 1. v2.0：把语音从「全互联 mesh」换成「混合转发」

**结论**：2.0 只做这一件事——让 10 人以上的房间真正能用，不加新功能。

- 现在 13 人上限下，每人要编码 N-1 路、维持 78 条媒体连接，**瓶颈是每台机器的编码**，
  不是带宽。代码注释里自己写明了。
- 推荐"混合转发"：小房间（2–3 人）继续 P2P，大房间切 SFU/转发，不推翻重来。

**要拍板**：
1. 2.0 只做这一件，同意吗？
2. 上限 13 → 20，还是先只解决"9 人也不卡"？（建议后者）
3. 保留小房间走 P2P？（建议保留）

## 2. 桌面端交互审查（P0 优先）

**结论**：桌面端有一批"能用但难受"的问题，P0 两条最影响日常：

1. **键盘焦点几乎不可见**——全站 100+ 可交互元素只有 1 个写了 `focus-visible`，
   Tab 切控件完全靠猜。修法：全局 `:focus-visible { outline: 2px solid var(--vx-accent); outline-offset: 2px; }`。
2. **没有任何功能快捷键**——桌面端没有"闭麦/离开/推流"的键盘入口。

P1/P2 是信息密度与打磨（设置分层、成员卡分组、空状态文案），清单见归档原文。

**要拍板**：P0 这两条是否现在就做（改动小、风险低）。

## 3. 共享屏幕画质

**结论**：问题不在"参数不够高"，而在三件事：

1. 观众看不到**为什么糊**（是共享端编码跟不上、自己网络差、还是 SFU 跨境丢包）；
2. **没有反馈回路**：观众端真实接收质量传不回共享端，共享端只能猜；
3. SFU 链路的 jitter buffer 默认 **3 秒**，看游戏/演示时"糊"之外还"慢"。

**最该先补的**：观众端把"收到多少分辨率/丢多少包"广播回共享端（成本最低，收益最直接）。

**要拍板**：默认档位是否改 1080p30；SFU 延迟默认值是否动；P2P 观众阈值是否放宽到 3 人。

## 4. 国内中继 / 语音丢包

**结论**：弱网抖动主要发生在**跨境段**，治本是在国内加一个 coturn 节点（约 ¥100/月），
`/ice` 多返回一条地址，ICE 自动择优，用户零设置。

**推荐路线**：
1. 先花 0 元测量：两人各 `ping/mtr 5blong.site`，对比丢包；房间里各提交一次反馈对比 `loss_pct`。
2. 确认丢包在跨境段 → 买杭州/上海轻量服务器跑 coturn。
3. 还想再榨一点 → 自适应码率（收益有限，免费）。

**决策点在第一步**：先测再花钱。
