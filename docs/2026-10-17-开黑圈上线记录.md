## 二、新功能：开黑圈

### 2.1 房间与编制
- 独立子系统（`src/client/game/`），**与语音房完全隔离**：独立引擎 `GameMesh`、独立界面、独立协议（`g` 系列消息）。
- 房间类型：开黑圈固定电竞主题（深色霓虹、随早/中/晚/夜变色），不提供雪原/万圣夜切换。
- 三栏编制板：**进攻方 / 待分队 / 防守方**，空位有“虚位以待”占位卡。
- 认领方式：**本人点选为主 + 房主可拖拽/菜单纠错**；房主可解锁每队人数上限（应对 6v4）。
- 容量：代码支持 20 人，当前启用 15 人。
- 记分：房主 +/- 与清零。

### 2.2 语音规则（核心）
| 我在哪 | 我能听到 | 谁听得到我 |
|---|---|---|
| 待分队 | **全房**（两队 + 待分队） | 只有待分队的人 |
| 进攻方 | 只有进攻方队友 | 只有进攻方队友 |
| 防守方 | 只有防守方队友 | 只有防守方队友 |

实现方式不是“调音量”，而是**连接拓扑**：
- 队伍 → 只与本队建立连接；
- 待分队 → 与所有人建立**单向通道**（发静音流、只收对方），所以“听全房但不打扰队伍”；
- 队伍**永远不会**主动连接待分队，从根上避免“队伍听到待分队”。

### 2.3 音频能力
- **麦克风增强**：底部滑条 100%–400%，是本地的**真 GainNode**（不是 UI 摆设）。
- **每人接收音量**：成员卡右侧「🔊 100%」按钮 → 滑条 0–200%，按游戏 ID 本机记忆，只影响自己听到的效果。
- **AI 强降噪**：RNNoise 接入，默认开、可关（与语音房同一条管线）。
- **音频设备选择**：底栏「⚙ 音频设备」→ 麦克风 / 扬声器下拉（切麦走 `replaceTrack` 热切换，切扬声器走 `setSinkId`），本机记忆。
- **说话者高亮**：说话时卡片青色发光、头像呼吸光圈、三格声波跳动、名字加粗；靠实时电平检测（160ms 采样），不是假动画。

### 2.4 本局小结
离开或关房时弹出：比分、房间时长、按队分组的成员「在场 X 分 / 发言 X 分」。

### 2.5 使用教程
首次进入自动弹出 5 条图文引导：填游戏 ID → 待分队 → 认领边 → 队伍隔离 → 记分/音量。

### 2.6 创建权限（不泄露任何密钥）
- **创建码**：管理员在后台生成（如 `BLONG-XXXX`），群友在客户端激活，30 天内免码建房。
- **员工令牌**：主令牌可签发“运营”令牌（scope=game，90 天，可吊销），对方打开 `/game-admin?staff=...` 只能生成/吊销码，看不到反馈与房间数据。
- 密钥只存在于 Worker Secret 与本地 `.dev-secrets.json`，前端只拿到 HMAC 签名结果。
- **吊销立即生效**：建房前会向 `/game/verify` 核验，吊销后点击创建会被拦并提示。

## 三、今天修掉的问题（全部来自实测）

### 3.1 语音房（历史遗留）
**「麦克风音量调到 200% 没效果」**
根因：浏览器 AGC（自动增益）与手动增益互搏——手动 ×2，AGC 自动 ÷2，净效果≈0。
修复：音量 >100% 时自动挂起 AGC（`applyConstraints`），回到 ≤100% 恢复。开黑圈同样处理。

### 3.2 开黑圈（按发现顺序）
| 问题 | 根因 | 修复 |
|---|---|---|
| 客户端激活报 `Unexpected token '<'` | 桌面端页面在 `tauri.localhost` 本地协议，相对路径打到本地资产返回 HTML | 接口用绝对地址（照 `/ice` 口径），并给 Worker 补 CORS |
| 客户端又报「网络异常」 | 跨域 POST 的 OPTIONS 预检没人应答 | `/game/*` 增加 CORS 预检（204 + ACAO） |
| 刷新后台就多生成一个码 | POST 后没有重定向（表单重复提交） | PRG：处理完 302 回页面，提示随参数带回 |
| 操作日志时间差 8 小时 | Worker 按 UTC 渲染 | 统一按 `Asia/Shanghai` 渲染 |
| 吊销了还能建房 | ①客户端“试用令牌”绕过校验 ②校验语义写成“次数必须>0” | 删除试用兜底；次数只约束激活，吊销/过期才拦 |
| 建房失败没提示 | 弹窗在 `finally` 里无差别关闭 | 成功才关，失败留在弹窗内并顶部红色横幅 |
| 折叠点了没反应 | `<details>` 被插在 `<table>` 内部（非法嵌套） | 折叠块移到表格外 |
| 折叠展开后列错乱 | 展开区没有表头 | 每个折叠表自带表头 |
| 后台 1101 崩溃 | 重构后残留 `dead` 变量引用 | 清理残留 |
| 各端名单不一致 | 访客只处理了 welcome/kick，**没处理名册广播** | 访客持续应用 `groster` 并重建音频 |
| 第一次换队听不到 | 切队时保留了“待分队时期”的静音连接，且跳过建新连接 | **队伍一变就全量重建所有连接** |
| 回待分队没声音 | 待分队被实现成“只听待分队” | 改为“听全房”：对队伍建立静音单向通道 |
| 说话特效不亮 | 分析器节点没有下游，不参与处理（电平恒 0） | 接一个增益为 0 的“静音汇点” |

### 3.3 界面与文案（业主逐轮验收）
- 教程弹窗浅字压米色底看不清 → 游戏内弹窗统一电竞深面板。
- 创建/加入弹窗太素、标签与输入挤一行、“激活”按钮竖排 → 重排为“标签在上、输入整行”，顶部双色光条与光晕。
- 创建弹窗点空白误关丢内容 → 背景点击不再关闭。
- 首页三个入口混淆 → 分区卡片，明示“分队内战用这个，平时连麦用语音房”。
- 后台裸表格 → 对齐 `/rooms` 暖色版式（统计卡 + 分区标题 + 空态盒），有效/已吊销分列，默认 5 条折叠。
- 新生成码不醒目 → 紧凑胶囊卡片（大码 + 一键复制），只显示最近一条。
- 员工令牌给的是相对路径（对方打不开）→ 完整 `https` 登录链接 + 复制按钮。
- 底栏“关闭开黑圈”深底不可见 → 红色实底白字。

## 四、运维与后续

### 4.1 后台入口（主域名 `https://5blong.pages.dev`）
| 页面 | 地址 | 用途 |
|---|---|---|
| 开黑圈运营 | `/game-admin?staff=<主令牌>` | 生成/吊销创建码、签发员工令牌、看操作日志 |
| 意见反馈 | `/admin?token=<主令牌>` | 意见反馈与状态流转 |
| 在线房间 | `/rooms?token=<主令牌>` | 实时房间与历史遥测 |

主令牌在 `.dev-secrets.json` 的 `feedbackToken`；`npm run feedback:admin url` 可打印。

### 4.2 数据结构（D1 `5blong-feedback`）
- `game_codes`：创建码（码、备注、剩余次数、到期、是否吊销）
- `staff_tokens`：员工令牌（只存哈希、scope、到期、吊销）
- `game_audit`：操作日志（时间、操作者、动作、详情）

### 4.3 发版流程（今天跑了很多次）
```
npm run check            # 类型检查 + 245 项测试 + 构建，必须全绿
npm run bump -- x.y.z    # 更新版本、提交、打标签
git push origin main     # 与标签两处都必须成功
git push origin app-vX.Y.Z
```
- GitHub 网络不稳时：`GIT_CONFIG_COUNT=1 ... proxy=""` 空代理覆盖 + 多端口轮询 + 后台重试。
- 发版后必须核对：`/desktop/latest.json` 版本、首页 bundle hash、`/game-admin` 200、CORS 预检 204。
