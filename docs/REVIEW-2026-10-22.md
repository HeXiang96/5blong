## 一、摘要

| 维度 | 结论 |

## 二、UI 设计评审

### 2.1 信息架构：关键设置藏得深

| 问题 | 位置 | 影响 |

### 2.2 状态与实现不一致（最容易挨骂的一类）

| 现象 | 根因 | 位置 |
|---|---|---|
| 没麦克风时按钮仍显示"麦克风开"，队友听不到 | 按钮只看 `muted` 不看 `hasMic`；`setMuted` 在 `localStream=null` 时什么也没做 | `RoomView.tsx:1278/1291`、`engine.ts:820-828` |
| 设置里关掉"进房默认静音"，进房还是静音 | `joinMuted` 全项目无消费点，所有进房路径硬编码 `true`；且 `loadSettings` 缺字段时返回 `false` 与默认值相反 | `use-voice.ts:1010/1032/1384`、`settings.ts:133/163` |
| 共享说明写"观众 ≤4 走直连"，代码是 ≤2 | 文案未随 `autoTransportFor` 改 | `RoomView.tsx:1537-1545` vs `screen-share.ts:429` |
| 开黑圈被踢 / 房主关房 → 界面直接消失，无任何提示 | `kicked`/`ended` 写了状态但无渲染点，`GameEntry` 在 `!prompt` 时 `return null` | `use-game.ts:217-237`、`GameEntry.tsx:94` |
| 点"复制"打勾，其实没复制 | `onCopyCode()` 是 `void`，无条件 `flash`；`clipboard.writeText` 不 await | `RoomView.tsx:904-921`、`GameEntry.tsx:74-76` |
| 单向自愈已恢复，红条挂一整局 | `status("error")` 写进 `error` 后无人清；`clearError` 未接 | `game-mesh.ts:707-714`、`use-game.ts:207` |
| 小结里对面全队"在场 0 秒" | `memberStats` 只在自己进房/音频挂上时建，跨队从不建 | `game-mesh.ts:1109-1116` |

**这一类问题的共性**：状态是"单向写的"——某个事件写了状态，但没有对应的复位或渲染。建议统一成"每个可见状态都有唯一数据源 + 明确的复位路径"，并在 UI 层做一次"状态矩阵"梳理（见 3.2）。

### 2.4 可访问性

- 共享按钮是弹层触发器，却缺 `aria-expanded`/`aria-haspopup`（同页其他菜单都有）；10 个选项按钮无 `aria-pressed`，选中态只靠颜色（`RoomView.tsx:1394-1419`）。
- 灯箱 `role="dialog"` 但无 `aria-modal`、不困焦点，背后 13 个猪按钮仍可 Tab 到（`PenTV.tsx:441`）。
- 聊天侧栏关闭只是 `translateX(102%)`，`aria-hidden` 为 true 但内部输入框仍在 Tab 序列 —— **看不见却在打字，回车会把半句话发出去**（`RoomView.tsx:1653`）。
- 13 只猪是 13 个 `button`，`aria-label` 只有名字，"点击调整音量"只在 `title` 里（`PigPen.tsx:1133`）。

### 2.5 文案与术语

同一个东西四种叫法：按钮"共享"、提示"电视被 XX 占着"、菜单"一块幕布"、灯箱"共享屏幕"；"转发"（SFU）与"中继"（TURN）是两个机制却像同义词；"闭听"与"静音"在不同面板混用。
**建议**：出一份 8 条术语表（共享/电视、直连/转发、中继、闭听、增强、静音、上麦、圈/房），全站替换，并在 SHARE 菜单里统一为"直连 / 转发"。

## 三、优化方案（分期）

### 第一期（本周，只做"止血"）
1. **媒体呼叫鉴权**（见 4.1 P0）：`onIncomingCall` 校验 `call.peer ∈ members` 或带一次性 nonce，否则 `close()`。
2. **反馈一致性三件套**：复制成功/失败走真实结果；切设备失败必须可见；被踢/关房必须有提示页。
3. **麦克风按钮与 `hasMic` 联动**：无麦时按钮变"申请麦克风"（点击重新 `acquireMic`），不再假装"麦克风开"。
4. **`joinMuted` 接通**（或直接删掉这个开关，别留死开关）。
5. **共享说明文案**改成 ≤2，与代码一致。

### 第二期（两周，结构与可测）
1. 共享菜单定稿为三段：`画质（2×2） / 声音（三选一 + 选中项详情） / 方式（三选一 + 一行代价说明）`，并把"本次将用…"改为**结果句**（"将直连 · 2 位观众 · 每人 4 Mbps"）。
2. 灯箱加可见组标题 `影音偏好`，把 6 个胶囊分为两行（画质 / 延迟）。
3. 统一"状态徽标"组件：`连接中 / 直连 / 转发 / 中继 / 已断开`，颜色 + 图标 + 短文案三通道（不只靠颜色）。
4. 错误条分级：`error`（需处理，可关闭）/ `warn`（自愈中，自动消失）/ `info`。
5. 响应式：820 宽底栏、超宽矮灯箱、游戏卡片菜单、教程弹窗四处补 `max-height`/`wrap`。

### 第三期（一个月，设计系统）
1. 抽 tokens：间距（4/6/8/12）、圆角（10/14）、字号（10/11/12/13）、语义色（选中/危险/禁用/中继中）。
2. 按钮状态矩阵：默认/悬停/激活/选中/禁用/加载，全部有实现，避免"看起来能点其实没反应"。
3. 键盘与读屏：所有弹层 `aria-modal` + 焦点圈禁 + `Esc` 关闭；选项组 `role="radiogroup"` + `aria-checked`。
4. 空态与加载态规范：列表空 8 处、加载 5 处目前各写各的。

## 四、技术审查摘要

### 4.1 安全（P0）
| 项 | 说明 |
|---|---|
| **P0 未授权媒体呼叫** | `onIncomingCall` 对任何 `call.peer` 无条件 `answer(outgoingStream)`（`engine.ts:3385-3438`）。房主 ID = `5b-h-` + 房间码，可被枚举；攻击者连上信令后 `peer.call(房主ID)` 即可**收走房主麦克风**并向其扬声器注入音频，房主界面看不到新成员 |

### 4.2 安全（P1，摘要）
- 4 位房间码 + `proof === ""` 直接放行 → 任意人可进任意在线房间旁听（`protocol.ts:94-103`、`engine.ts:1505-1523`）。
- 房主 ID 可被抢注；裸码访客不校验房主 proof → 假房主可清名册/禁言。
- `/ice` 无鉴权 + 23 小时全局限共享凭据 → TURN 额度可被盗用（且客户端缓存 12h，最坏持有过期凭据 11h）。
- `/sfu/*` 无客户端鉴权 → 任何人可建会话、消耗 Realtime 额度。
- 任意 WS 客户端可伪造 `ROOM-SNAPSHOT` 写生产 D1；断开时全 Hub 广播 `LEAVE`（O(n) 放大）；单实例总机每条消息 O(n) 重建 peer 表。

### 4.3 语音引擎（P1）
- 建链判据只看 `hasMic` 不看 `muted`：默认静音进房被当成"0 包异常"，20 秒后反复拆建、1 分钟后显示"连不上对方"（`engine.ts:3541-3550`）。
- `kick` 的 `reason` 在解析层被丢弃 → "超时踢人自动重进"是死代码（`protocol.ts:748`）。
- 访客停播后 `screenCalls` 未清 → **第二次开播老观众永远黑屏**（`engine.ts:1897`）。
- `identity` 更新后 `GuestRecord.member` 与新对象脱钩 → 改名后麦/闭听图标不再更新、重连可绕过禁言（`engine.ts:1415`）。
- `speaking` 只有"访客→房主"方向 → 除房主外所有人的说话高亮与小结时长失效（`engine.ts:3032`）。
- `handleHello` 在两个 await 后才写名册且不查 `conn.open` → 可产生永久幽灵成员（占名额）。

### 4.4 屏幕共享（P1）
- 并发点两次共享 → `sharePubRef` 被覆盖/清空，PC 与 SFU 会话无人回收（`use-voice.ts:720`）。
- `publishScreenOnce` 无 `try/finally`，失败必留半开 PC（`screen-share.ts:1696`）。
- 订阅 `stop()` 只 `pc.close()`，**不通知 SFU 关轨** → 服务端持续转发，配额泄漏（`screen-share.ts:1978`）。
- 档位记忆覆盖用户显式选择：选"超清"却按上次被降到的 380p 开播（`screen-share.ts:1043`）。
- SFU 发布路径不传 `maxBitrate` → "容量不足"判据永不生效，只能等编码器自报（`screen-share.ts:1789`）。
- `postJson` 无超时：`/sessions/new` 可永久挂起，停播时 PC 也不关（`screen-share.ts:579`）。
- 发布端 `onLost` 从不传入 → SFU 断线后共享者界面仍显示"正在共享"（`use-voice.ts:695`）。
- **观众侧延迟三个按钮当前无效**：`setScreenLatency` 遍历的是发送方向的 `screenCalls`，观众没有（`engine.ts:1843`）。

### 4.5 开黑圈（P1）
- 换队被房主拒绝无回执 → 界面停在"幻影队伍"，随后按错队伍重建连接，越点越乱（`game-mesh.ts:324-327`）。
- 被踢/房主关房无任何提示（同 2.2）。
- 小结里跨队人员"在场 0 秒 / 发言 0 秒"。
- 进房失败不释放麦克风：关掉弹窗后系统仍显示"正在使用麦克风"（`game-mesh.ts:158-198`）。
- "待分队听全房"这条**唯一不设看门狗**的链路，恰好是唯一的单向通道（`game-mesh.ts:663`）。

### 4.6 设备与设置（P1）
- 麦克风打不开时异常被 `catch {}` 吞掉，`micErrorMessage()` 的四句人话从不显示（`engine.ts:4455`）。
- 通话中切麦克风不生效（只改增益/降噪），但提示文案让人"去设置里重选"（`use-voice.ts:1163`）。
- 切扬声器失败的消息走 `status("connected", …)`，被 UI 的 connected 分支丢弃 → 仍是静默失败（`devices.ts:150`）。
- loopback 启动路径三处抛错不走 `cleanup()` → 每次失败残留一个 48k AudioContext，反复点共享会耗尽上下文（`loopback.ts:195`）。

- 共享声音只采被共享应用（Rust 进程级 INCLUDE + 窗口标题反查 PID）、整机采集改为排除 WebView2 进程树、共享提示如实显示实际模式。

- 前一轮已修 15 处（单向判据、播放链看门狗、名册截断、glare、自愈计数、AGC、duck 复位、Worker 计时等）。

## 七、验证建议

1. **P0 复现**：自建一个 PeerJS 客户端连 `wss://5blong.pages.dev/peerjs`，用已知房主 ID `peer.call()`，观察房主是否直接应答（有声音即命中）。
2. **静音进房**：两人都默认静音进房，10 分钟内看是否出现"连不上对方"。
3. **13 人满员**：坐满后看名册是否全员一致、是否有人被踢出名单。
4. **共享二次开播**：同一人开播→停播→再开播，老观众是否还能看到画面。
5. **820×600**：缩到最小窗口，看底部托盘与灯箱是否完整可点。
