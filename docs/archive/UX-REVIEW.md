# 5blong 交互审查与优化方案（桌面版）

> 2026-11-01 · 审查范围：**仅桌面**（客户端 + 桌面浏览器），不涉及手机
> 依据：真实渲染截图（1440 / 1280 / 1024 三档）+ 代码核查

---

## 一、范围修正

上一版按 390px 手机审的（52 个触控目标不足、tab 折行等）。业主明确**只在电脑上用**，那批结论作废，本版重做。

桌面端不关心 44px 触控目标（鼠标定位精度足够），真正该看的是四件事：

1. **键盘能不能走完全流程**（Tab 顺序、焦点可见、Esc 退出）
2. **常用操作有没有快捷键**（挂机开会/开黑时，静音是每分钟都要做的动作）
3. **窗口被拖动/缩小后布局还成不成立**
4. **大屏下空间利用率**（1440 甚至更宽时，是不局促还是散架）

---

## 二、体检结果

| 维度 | 现状 | 判断 |
|---|---|---|
| 键盘焦点可见 | 全站 **1 处** `focus-visible`（仅 `.vx-tile-interactive`） | ❌ 严重 |
| 功能快捷键 | **零**（只有输入框的 Enter/Esc、以及绕过自动播放的一次性 keydown） | ❌ 缺失 |
| 窗口最小尺寸 | `tauri.conf.json` 里 `windows: []`，代码中**未设 min_size** | ❌ 可拖到崩溃 |
| 悬停反馈 | 77 处 `:hover` | ✅ 充分 |
| 横向溢出 | 1024 / 1440 实测均为 0 | ✅ 正常 |

**一个反直觉的对比**：

同一间 8 人房，**1024×768 比 1440×900 好看得多**。

- 1024 下：猪聚集、名字清楚、控制条占比合理
- 1440 下：猪散在 1080px 宽、200px 高的范围里，中间大片留白，上半屏约 **1/3 是空的**

说明布局**缺少最大宽度约束** —— 不是"小屏不够用"，是"大屏没有收住"。

## 三、P0：桌面端必须先解决

### P0-1 键盘焦点几乎不可见

全站 100 多个可交互元素，只有 1 个写了 `focus-visible`。用 Tab 走一遍，**根本看不出焦点在哪**。

这在桌面端是硬伤 —— 不只是无障碍问题：用户用 Tab 切输入框、切按钮时完全靠猜。

```css
/* 全局兜底，放在 styles.css 顶部 */
:focus-visible {
  outline: 2px solid var(--vx-accent);
  outline-offset: 2px;
}
/* 圆角元素别让 outline 出棱角 */
.vx-btn:focus-visible,
.vx-icon-btn:focus-visible {
  outline-offset: 2px;
  border-radius: inherit;
}
/* 鼠标点击时不显示，只有键盘操作才显示 */
:focus:not(:focus-visible) { outline: none; }
```

### P0-2 没有任何功能快捷键

语音房里最高频的三个动作：**静音/开麦、闭听、举手**。现在全部要用鼠标点底部控制条。

挂机开会、开黑打到一半时，手在键盘上，还要去够鼠标 —— 这是每天都会难受的点。

建议键位（避开浏览器/系统冲突）：

| 键 | 动作 |
|---|---|
| `Space` | 静音 / 开麦（输入框聚焦时自动让行） |
| `D` | 闭听开 / 关 |
| `H` | 举手 / 放下 |
| `Esc` | 关弹窗 / 退出灯箱（已有部分实现，需覆盖全场景） |

```tsx
useEffect(() => {
  const onKey = (e: KeyboardEvent) => {
    const el = e.target as HTMLElement;
    if (el.tagName === "INPUT" || el.tagName === "TEXTAREA" || el.isContentEditable) return;
    if (e.metaKey || e.ctrlKey || e.altKey) return;
    if (e.code === "Space") { e.preventDefault(); onToggleMute(); }
    else if (e.key.toLowerCase() === "d") onToggleDeaf();
    else if (e.key.toLowerCase() === "h") onToggleHand();
  };
  window.addEventListener("keydown", onKey);
  return () => window.removeEventListener("keydown", onKey);
}, [onToggleMute, onToggleDeaf, onToggleHand]);
```

配套：底部按钮的 `title` 里写上快捷键（`静音 (Space)`），否则没人知道。

### P0-3 窗口可以拖到布局崩掉

Tauri 配置里 `windows: []`，代码里也没设最小尺寸。用户把窗口拖窄到 600px，招牌会换行、控制条会挤、猪会重叠。

```json
// tauri.conf.json
"windows": [{ "width": 1280, "height": 800, "minWidth": 1024, "minHeight": 680 }]
```

**1024 是实测下布局最稳的下限**，低于这个值体验明显下降，不如直接不让拖。

## 四、P1：体验与信息密度

### P1-1 大屏下内容散架（≥1400px）

房间页：猪分布在 1080px 宽的范围里，篝火在正中，四周大量空白；招牌 560→740px 变宽但内容没变多，纯粹是 padding 在撑。

```css
/* 给"舞台"一个上限，大屏居中，别再无限拉伸 */
.vx-room-stage {
  max-width: 1180px;
  margin-inline: auto;
}
```

### P1-2 首页在 1440 下是一张 400px 的窄卡片

左右各留 500px 空白，整体像"手机页面放到了大显示器上"。桌面有横向空间，却只用了中间 28%。

两条路：

- **保守（推荐先做）**：卡片放大到 `max-width: 560px`，标题字号上调一档，让首屏更有分量
- **彻底**：≥1280px 改两栏 —— 左侧氛围 + 卖点，右侧操作卡

### P1-3 聊天是弹窗，浪费了横向空间

桌面端聊天完全可以常驻右侧（320px 固定栏），而不是点了才浮出来。开着聊天看猪圈，比九个人挤在画面里更舒服。

这条要动结构，风险中等，建议放最后做。

### P1-4 说明文字在桌面反而更难读

房间页「听公告」是 11px 灰字，首页底部说明是 10.5–11px。桌面观看距离比手机远，这些字**实际比手机上更难辨认**。

建议辅助文字统一 12px 起，且对比度 ≥ 4.5:1。

## 六、设计令牌（桌面口径）

```css
:root {
  /* 桌面用鼠标，24px 够；但要给 hover 留出热区余量 */
  --tap-min: 32px;

  /* 字号：桌面比移动端可以再收紧一档，但辅助文字不低于 12 */
  --fs-xs: 12px;  --fs-sm: 13px;  --fs-md: 14px;
  --fs-lg: 16px;  --fs-xl: 20px;  --fs-2xl: 26px;  --fs-3xl: 34px;

  /* 内容最大宽度：房间与首页各自收住，避免大屏散架 */
  --w-stage: 1180px;
  --w-card: 560px;

  --sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px; --sp-6: 24px;
}
```

## 七、验收方式（都能自动化）

1. **键盘走查**：不碰鼠标，从首页进房 → 静音 → 闭听 → 开聊天 → 退出，全程焦点可见、无死路。
2. **三档截图**：1024 / 1280 / 1440 各截一张房间与首页，对比空白占比。
3. **窗口拖拽**：把客户端窗口从 1280 拖到 1024，确认布局不破、招牌不折行。

## 八、建议顺序

| 批次 | 内容 | 工作量 |
|---|---|---|
| 1 | P0-1 焦点可见 + P0-3 窗口最小尺寸 | 约 15 行 |
| 2 | P0-2 快捷键（含按钮 title 提示） | 约 30 行 |
| 3 | P1-1 / P1-2 大屏约束与卡片放大 | 约 20 行 CSS |
| 4 | P1-3 聊天常驻侧栏 | 动结构，需评审 |
| 5 | P2 打磨 | 零散 |

前三批加起来不到 70 行，能解决桌面端最扎手的三件事：**键盘能用、大屏不散、窗口不崩**。
